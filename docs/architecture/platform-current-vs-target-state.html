1RAG retrieval backend - the one real current/target gap in the live request path

Current

The Gateway's BACKEND_SERVICE_URL still points at hrb_chatbot_service. Every real genai-rag / single-agentic-rag / multi-agentic-rag query in production is served by this monolith repo, same as before the microservices split began.

Target

The intended steady state is hrb_rag_retrieval_service as a standalone repo serving all 3 retrieval modes. It's already built, provisioned, deployed, and live standalone (its own App Runner URL) - 3 real bugs found and fixed during its own smoke test, now resolved. The cutover itself (pointing the Gateway at it instead) is a deliberate, separate, not-yet-made decision.

Why this is the one gap worth calling out specifically: every other repo in the 7-service split (hrb_api_gateway_service, hrb_rag_ingestion_service, hrb_platform_components, hrb_chatbot_ui, hrb_common_libs) has already been cut over to its real target role. Retrieval is the only capability still served by its pre-split monolith, by explicit choice, not an oversight.
